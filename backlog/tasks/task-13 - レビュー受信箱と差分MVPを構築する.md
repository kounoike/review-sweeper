## Description
<!-- SECTION:DESCRIPTION:BEGIN -->
認証、PRの発見と絞り込み、メタデータと差分の表示、コメント下書き、レビュー送信、チェック、テーマ対応からなる、最初に役立つレビューの流れを構築する。
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 GitHub認証を実装する。
- [ ] #2 ユーザーがレビューを依頼されたPRを取得する。
- [ ] #3 直接のレビュー依頼、割り当てられたPR、チームへのレビュー依頼、前回レビュー以降に更新されたPRでレビュー受信箱を絞り込めるようにする。
- [ ] #4 受信箱にリポジトリ、番号、タイトル、作成者、経過時間、変更ファイル、追加・削除行数、チェック、レビュー状態、準備状態を表示する。
- [ ] #5 差分サイズと変更ファイル数からレビューコストを見積もる。
- [ ] #6 ローカルworktreeなしでPRメタデータ、コミット、コメント、チェック、GitHub差分を取得する。
- [ ] #7 統合表示と分割表示の差分ビューアーを実装する。
- [ ] #8 ソースと差分の表示に構文ハイライトを追加する。
- [ ] #9 空白の非表示、ファイル移動、ハンク移動、閲覧済み状態、変更のない領域の折りたたみに対応する。
- [ ] #10 完全なソースビューアーと、差分・ファイル全体の文脈を素早く切り替える機能を実装する。
- [ ] #11 インラインレビューコメントの下書きに対応する。
- [ ] #12 保留中のレビューをApprove、Request changes、Commentとして送信する。
- [ ] #13 選択中のPRのチェックとCI状態を表示する。
- [ ] #14 ユーザーの前回レビュー以降の差分に対応する。
- [ ] #15 ライト、ダーク、システムのテーマに対応する。
<!-- AC:END -->

## Definition of Done
<!-- DOD:BEGIN -->
- [ ] #1 テストと該当するチェックが通る
- [ ] #2 文書が更新されている
- [ ] #3 リグレッションがない
<!-- DOD:END -->
